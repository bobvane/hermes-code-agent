# 开发目标：每角色不同模型 v2（OpenCode × Codex 强强联合版）

> 状态：已定目标，未实施。Bob 于 2026-08-25 拍板。
> 交互原则（Bob 定）：Skill 只负责**提醒**，不执行切换；用户换了就获益，不换照样编程下去。

## 合成哲学

OpenCode 给声明式（角色↔模型固定映射，稳定可预期），Codex 给弹性思想（按步骤难度调配）。静态映射覆盖九成收益（PLAN 难/BUILD 简单事先可知），是主流形态。

## 最强两家机制

- **OpenCode per-agent model**：每个 agent 配置文件里声明模型字段，角色创建即绑定，声明式、一次配好全局生效
- **Codex per-turn model**：每回合可换模型，动态弹性，但无固定"角色=模型"映射

## 三方裁决结论

| 维度 | OpenCode | Codex | 我们 | 裁决 |
|---|---|---|---|---|
| 角色↔模型声明式绑定 | ✓配置字段 | ✗ | 半(仅文字建议) | 采纳 OpenCode → 升级为结构化映射表 |
| 运行时动态切换 | ✗ | ✓ | /model 手动可用 | Codex 方式最优但 Skill 无法自动路由 |
| 自动化 | 全自动 | 全自动 | ✗手动 | **形态硬限制**(已接受)：请求路由归宿主 |

## 开发目标内容

1. **角色-模型档次映射表**写入 SKILL.md（对标 OpenCode 声明式）：
   - PLAN 步骤 → 强档
   - BUILD/机械修改步骤 → 经济档
   - REVIEW 步骤 → 中档
2. **步骤边界检查动作**：进入新步骤时对照映射表检查当前模型档次，不符则向用户输出一行提醒（含 `/model` 切换命令）
3. **非阻断原则（Bob 定）**：只提醒不等待——用户切换则获益，不切换流程照常继续
4. 全自动请求路由 = 形态硬限制，如实标注不做
