# 开发目标：权限审批分级 v2（Codex × Cline 强强联合版）

> 状态：已定目标，未实施。Bob 于 2026-08-25 拍板。
> 特殊性：六个功能中唯一可"完全照搬"的——本质是规则表知识，非运行时能力，Skill 形态无障碍。

## 合成哲学

Codex 给分档框架（按信任级别分级），Cline 给操作类型白名单（按工具类型区分）。融合 = **一张二维分级表**：行=操作类型，列=审批档位。

## 最强两家机制

- **Codex 四档 approval policy**：untrusted / on-request / on-failure / never —— 宿主执行前查表决定是否弹窗
- **Cline 按工具类型 auto-approve 白名单**：UI 配置哪些工具免确认，其余每次确认

## 开发目标内容

SKILL.md 写入操作分级表（完全照搬两家逻辑）：

| 档位 | 来源 | 操作类型 | 动作 |
|---|---|---|---|
| L0 免审 | Cline auto-approve | 读文件/搜索/项目内 git status、diff 等只读操作 | 直接做 |
| L1 常规 | Codex on-failure | 项目内文件编辑、跑测试/构建 | 直接做，失败如实报告 |
| L2 审批 | Codex untrusted + Cline 逐次确认 | 安装依赖、项目外写文件、git commit/push、网络下载 | clarify 先问，批准再做 |
| L3 红线 | 两家共同(never 自动化的部分) | 删除数据、改系统配置、发消息/公开发布、密钥操作、受限路径(~/.ssh/*key*等) | 必须 clarify 且默认建议否决 |

配套规则：
- 执行前对照本表；L2/L3 用 clarify 弹给用户
- 模型忘查表时无人强制 → 事后由 plancheck 类审计兜底危险操作（提示词机制共同属性，如实标注）
- 弹窗体验与 Cline 确认框一致："动手前用户看到并点头"

## 与现有实现的差异

现状只有"危险命令拦截清单+管理员操作先问"的粗粒度两条；本目标将其升级为四档结构化分级表，覆盖面从"命令"扩展到"所有操作类型"。
