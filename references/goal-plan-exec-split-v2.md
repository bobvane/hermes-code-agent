# 开发目标：计划/执行分离 v2（Codex × Cline 强强联合版）

> 状态：已定目标，未实施。Bob 于 2026-08-25 拍板作为该功能的开发目标。
> 政策合规：两来源功能均在六家对标表内。
> 讨论规则（Bob 定）：每个功能只挑最强两家讨论融合，不拉弱者对比。

## 合成哲学

Codex 的强 = 强制力（程序执行模式切换，模型无权参与）；Cline 的强 = 交互权（切换按钮交给人，人确认才放行）。两者是同一机制（双模式+权限差异）在不同层面的实现，不冲突可叠加：
**Codex 层给纪律，Cline 层给人眼——程序定规则，用户按开关。**

## 最强两家的机制拆解

### Codex CLI —— ModeKind 双模式
1. 两套独立系统提示词（Plan/Execute 各一 bundle），API 调用前由宿主替换
2. Plan 模式下写权限被程序过滤
3. 违规物理不可能（前两条叠加）

### Cline —— Plan/Act 用户切换
1. 同样双模式双提示词
2. 切换按钮在用户手里，方案过目、人点头才进 Act
3. 强制力一半来自"用户在场看着"

## 融合后的目标流程

```
任务开始 → clarify("进入哪个模式？" [PLAN / BUILD])
  ├─ 选 PLAN → 加载 PLAN 段指令文本（只读探索/分析/输出方案）
  │            提示词禁令：本模式下禁止 patch/write_file
  │   计划完成 → plancheck 审计（源码动了=违规→回滚）
  │             → clarify("计划已出，切换到 BUILD？")
  └─ 选 BUILD → 加载 BUILD 段指令文本（最小修改/每步验证）
```

## 四层实现映射（含形态硬限制标注）

| 层 | 来源 | 我们的实现 | 形态限制 |
|---|---|---|---|
| 1. 阶段门 | Cline | clarify 弹选项让用户确认模式切换 | 无 |
| 2. 双段指令文本 | Codex 提示词部分 | SKILL.md 内嵌两段完整模式准则，边界处声明切换 | 系统提示词外置换做不到，用内嵌替代 |
| 3. 违规审计 | 我们对"收权"的补偿 | plancheck 对比 git 状态，计划期动源码=违规回滚 | 已有 |
| 4. 权限物理收窄 | Codex 核心 | ✗ 做不到——工具注册表归宿主，Skill 无运行时 API | **唯一形态硬限制，Bob 已接受** |

强制力差距一句话：Codex 里违规是不可能事件；我们这里是高概率被抓事件 + 用户全程知情。
