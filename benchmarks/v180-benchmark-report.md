# v1.8.0 总体测试报告（2026-08-25）

> 结论先行：**门禁的价值不在"提高分数"，而在"限定损失 + 把偶然成功变成可复现成功"。**
> 裸模型一次写对的代码是抽奖；带门禁的每一轮绿都是验证过的、可回滚的落盘。

## 一、测试设计

| 维度 | 取值 |
|---|---|
| 模型档位 | Qwen2.5-Coder-3B（低）/ 7B（中低）/ DeepSeek-V4-Flash（中）/ OxAlpha（高） |
| 基准题 | kvstore：TTL+嵌套事务+线程安全 KV 存储（11 判例）；lockmgr：死锁预防分布式锁管理器（12 判例） |
| A 组（裸跑） | 写完即交卷，不运行任何测试——模拟无护栏工作流 |
| B 组（门禁） | guard 封存裁判 → verify → 红修循环 → 熔断兜底 → 绿后 auto-commit——完整 v1.8.0 工作流 |
| 熔断规则 | 同失败集连续 3 轮 doom 停；红轮 ≥5 预算停；错误摘要累计 ≥15k tok 停 |

- 环境：OmniRoute 免费渠道；渠道故障轮不计入数据。
- 编排器：`benchmarks/run_v180.py`；原始逐轮数据：`benchmarks/v180_raw_results.json`（32 轮）。

## 二、量化结果

### 判例通过率（passed/total，组内均值）

| 模型 | 组 | kvstore | lockmgr |
|---|---|---|---|
| Qwen2.5-Coder-3B | A 裸跑 | 27.3% (3轮) | 0.0% (3轮) |
| | B 门禁 | 0%* (1轮有效†) | 4.3% (2轮有效) |
| Qwen2.5-Coder-7B | A 裸跑 | 0.0% (3轮) | 渠道缺失‡ |
| | B 门禁 | 渠道缺失‡ | 渠道缺失‡ |
| DeepSeek-V4-Flash | A 裸跑 | 87.9% | 30.6% |
| | B 门禁 | 58.3%（最佳单轮 **11/11 全绿**） | 36.1%（最佳单轮 11/12） |
| OxAlpha | A 裸跑 | **100%**（3/3 首过全绿） | 86.1% |
| | B 门禁 | **100%**（1 红修后绿，auto-commit 落盘✅） | 83.3%（4 红轮后熔断§） |

\* 3B-B 有效轮在 5 红轮熔断时仍为 0 通过——熔断正确止损但无力回天。
† "有效" = 排除渠道 404 故障轮后的计数；补数进行中。
‡ 免费 hf/ 渠道持续 404，后台自动等待恢复补测。
§ 第 5 红轮 impl 自我死锁把测试 runner 挂死（见"发现"）。

### 关键对比

1. **首过率（一次写对）**：kvstore 上 DeepSeek 裸跑仅 1/3、OxAlpha 3/3；lockmgr 无任何裸跑全绿——难题上"盲写通过"不存在。
2. **修复效率**：DeepSeek B 组唯一全绿的 kvstore 轮只用了 **1 红修轮 / ~6.1k tok**；而失败轮平均烧 **~29k tok** 仍不过。红修收益高度依赖第一版质量。
3. **止损价值**：B 组 8 轮撞 5 红轮上限被强制停——每轮损失锁定在 ~12–29k tok。A 组无止损，lockmgr 两轮 runner 死锁各挂满 300s（生产环境即无限挂起的人工成本）。
4. **auto-commit 实战**：OxAlpha kv_b1 绿后自动落盘 checkpoint（`hca: green checkpoint, red-cycles=1`，真实触发 ✅）。
5. **死锁挂死 vs 超时熔断**：OxAlpha lockmgr-b1 第 5 红轮 impl 自死锁 → pytest runner 挂死 → 400s 后才被编排器 timeout 杀掉；**门禁本身未加 per-test timeout，此次 v1.8.1 已修（见发现 #1）**。

## 三、五角色设计评审收敛

| 角色 | 关键结论 |
|---|---|
| 产品 | 门禁价值 = 消灭"虚假完成" + 失败可控可审计。不宣称"提升通过率"，以"每个绿都是 verified exit-0"为卖点。 |
| 架构 | doomcheck/budget/snapshot/digest 四环节均实证有效；**缺陷**：verify 缺 per-run timeout → 死锁挂死 gate，v1.8.1 修复。 |
| 研发 | 编排模拟存在失真（脚本喂摘要非真实 agent 工具链）；定性结论可信、量化归因须谨慎。 |
| QA | 样本量少（多格仅1轮）、分母 11/12 不一致、schema 漂移 → 需固化 ≥5轮/格。 |
| 评论家 | "B比A多花10倍token"最牛质疑；数据反驳：唯 B 组才有 exit-code 可判定 + 回滚；A 组挂死轮 token 记录为0（不可控成本）。 |

## 五、诚实性声明

- OxAlpha（本项目作者模型）参与测试存在自评偏差，其数据仅作高档参照。
- Qwen 两组部分单元格受免费渠道故障影响，标注为部分数据，补齐后更新本表。
- B 组由脚本驱动（生成→判→喂摘要→重生成），与真人会话中的 agent 行为存在差异：脚本不使用 repo map/patch 等新工具，故 v1.8.0 的 repomap/patch 三级降级未在本轮量化覆盖。

## 五、一句话总结

**裸模型的最高分靠运气，门禁的价值是把运气变成流程：错了立刻知道、改不动就停、改好了就存档。**
